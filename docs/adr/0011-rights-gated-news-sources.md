# ADR 0011: Rights-Gated News Sources and Media

**Date:** 2026-11-24
**Status:** Accepted

## Context

A public RSS or API endpoint is a technical distribution channel, not a license
to aggregate its content. Cointelegraph's terms prohibit independent automated
pipelines without written permission, and other publishers restrict automated
collection, caching, display, or image reuse. The previous default
`NEWS_FEED_URLS` list allowed any deployment to bypass editorial review.

The repository already solves cross-runtime drift for asset reference data with
a canonical TypeScript registry and a generated Python artifact. News sources
need the same bridge plus an explicit rights gate.

## Decision

- `packages/shared/src/news-sources.ts` is the canonical source registry.
- `apps/python/src/data/news/sources.generated.json` is committed, slim-safe,
  regenerated by `pnpm sync:news-sources`, and checked for drift in CI.
- Every source records automation rights, metadata rights, image rights,
  terms/license evidence, review dates, cadence, adapter, and image-host
  allowlist.
- A source is fetched only when it is enabled, automation and metadata rights
  are approved, and the current UTC date is before its exclusive review expiry.
- `NEWS_FEED_URLS` is removed; environment variables cannot enable a denied
  source.
- Cointelegraph and CoinDesk are disabled. SEC is the only enabled automatic
  source in this change. Federal Register and CoinGecko remain disabled until
  their adapters ship; CoinGecko also requires a paid API key.
- No approved source currently grants image hotlink rights. The product remains
  text/link-only and does not render third-party images.
- Ingestion stores metadata and links only. It does not copy full article bodies
  or download third-party images.
- Disabling a source stops new ingestion and `NewsRepo.list` immediately hides
  existing rows through the same registry. Data purge requires a backup and
  explicit operator approval.

## Alternatives Considered

| Option                          | Why considered                            | Why rejected                                                                         |
| ------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------ |
| Keep arbitrary `NEWS_FEED_URLS` | Flexible and simple                       | Bypasses rights review and makes production behavior unauditable                     |
| Treat public RSS as permission  | Zero legal onboarding                     | False; publisher terms can prohibit aggregation even when the feed returns 200       |
| Hotlink every feed image        | Closest to Cointelegraph's visual density | No selected source grants those rights; also creates tracking and availability risks |
| Copy images into S3             | Stable URLs and performance               | Creates a copy that normally needs a stronger license than hotlinking                |
| Manual curation only            | Lowest automation risk                    | Does not meet the scheduled-ingest product requirement                               |

## Consequences

**Positive:** production sources are reviewable, expiry-aware, and impossible to
enable through an environment typo. Python and Node share one generated source
of truth.

**Negative:** adding a source requires a code review and evidence update. The
initial feed is narrower and mostly regulatory until more permissions exist.

**Neutral:** source health and adapter expansion can be added without changing
the rights model.
